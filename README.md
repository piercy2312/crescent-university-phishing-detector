# Crescent University Phishing Detection Project (Stages 1-5)

A labelled synthetic dataset and a rule-based detector that mirrors the
four-stage phishing attack chain (lure email -> malicious link -> landing
page -> credential submission) against a **fictional** "Crescent University"
student portal. Everything is synthetic and runs entirely on localhost / inside
the VM. No real students, no real domains, no real credentials.

## Actual folder structure

```
build_dataset.py        ONE command to (re)generate all samples into samples/
rules/
  rules_config.json          the rule base: 12 rules across 3 stages
  landing_pages_manifest.json (rebuilt by build_dataset.py, always matches samples/pages)
engine/                 (this is the "detector")
  config.py                  allow-lists, suspicious TLDs, impersonation keywords, thresholds
  checks.py                  one condition-check function per rule ID
  parsers.py                 turns raw files into sample dicts
  engine.py                  the execution engine (score vs threshold -> verdict)
  mitigation.py              the response/mitigation layer
  run_detector.py            quick single-pass run + console accuracy report
  run_experiment.py          full timed experiment, 20 repeated passes
  metrics.py                 the four Chapter 5 metrics + two charts
  stress_test/               hand-crafted samples that deliberately EVADE the rules
samples/                (generated by build_dataset.py - now committed, not ignored)
  emails/   *.eml + labels.csv
  urls/     urls.csv
  pages/    *.html + labels.csv
scripts/
  submission_logger.py       the mock portal: serves the login page AND logs submissions
```

## How to run (from the repo root, in order)

```
python build_dataset.py            # 1. (re)generate the labelled dataset into samples/
cd engine
python run_detector.py             # 2. quick check: one pass, per-stage accuracy
python run_experiment.py           # 3. full timed experiment (20 passes) -> results.csv
python metrics.py                  # 4. Chapter 5 metrics table + two charts
python stress_test/run_stress_test.py   # 5. evasion demo (shows the rules' limits)
```

## To see the simulated portal in your browser

```
python scripts/submission_logger.py
```
Then open **http://127.0.0.1:5000/** in the VM's browser. You will see the
mock Crescent login page. Submitting it POSTs to `/collect`, which records the
field *names*, time and source in `scripts/submission_log.csv` - never the
password value. Stop the server with Ctrl+C.

## Safety notes

- All domains/IPs are reserved-for-documentation ranges (198.51.100.0/24,
  203.0.113.0/24) or fictional hostnames.
- The portal/logger binds only to 127.0.0.1 and stores field names, never values.
- Nothing here should ever be pointed at real domains, real students, or
  anything outside your own VM.
